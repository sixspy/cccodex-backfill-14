# cc-backfill-lab

CC_Codex 二期（26.11）**数据工程**产品线：**回灌补数台**（Falcon ASGI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**回灌窗口 → 按日切片计划 → 重放落库 → 覆盖对账**

与现有线正交（不是契约换版、水印、清单、留存、采集/ETL/同步/解析/编排/摄取）。
不碰外仓常见指纹（Feed 归并 / CDC 游标 / 质检签发 / Slicegate 类仓名）。

## 领域

- **所属领域**：数据工程
- **子方向**：数仓与数据湖（历史回灌 / 补数闭环）

## 片锁争用闭环（本期）

片键 = `目标表#切片日期`。同片连点、两侧调度抢同片，都必须只成功一次。

**占片取舍（全局只贯彻这一条）**：唯一索引 + 先核后写，挡后到。

- `slice_locks.slice_key` 唯一：一个片键只能有一把片锁；
- `backfill_target.slice_key` 唯一：目标表同片键只留一行；
- 事务统一 `BEGIN IMMEDIATE`，核与写在同一个写锁内完成。

被放弃的另一条路线「旁路片锁账册原子改写后再拒二次」不采用：它允许重复请求先把锁行/落库行
写进去再补拒，双份脏行会占库。占片闸口、重放、争抢编排全部走同一条路线。

**四处同看**（顶部标签页）：

| 视图 | 内容 |
|------|------|
| 占片闸口 | 占片成功亮 `Lxxxxxx` 片锁号；拒重亮 `Rxxxxxx` 拒重号并回短句；可一键跑「同片争抢一轮」 |
| 争用台账 | 每次占片尝试一行，拒重行带拒重号与片锁号；下方列出编排争抢记录 `CR-xxxx` |
| 片键详情 | 单片的可写态、片锁与可写是否对齐、目标行数、同片成功次数、全量台账 |
| 回灌进度 | 按唯一片键聚合，拒重不计数，同片键成功次数恒 ≤ 1，进度不翻倍 |

规则：

- 片锁与可写未对齐（切片非「待重放」却仍有可写期望、锁状态异常）→ 直接拦，409「片锁与可写未对齐」；
- 同片争抢一轮编排只留一条 `contention_rounds` 记录，闸口与台账同读该拒重号；
- 落败方二次重放一律拒重，目标表不新增行，切片计划里同片键成功次数只能为 1。
